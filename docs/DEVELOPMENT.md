# Разработка

Практическое руководство: что пересобирать, как добавлять фичи и на какие грабли
наступают чаще всего. Устройство проекта описано в [ARCHITECTURE.md](ARCHITECTURE.md),
сборка — в [BUILDING.md](../BUILDING.md).

## Подготовка окружения

```bash
cargo test                       # проверить тулчейн (GUI-зависимости не нужны)
cd ui && npm ci && npm run build # собрать фронтенд
cd ../src-tauri && cargo run     # запустить GUI
```

Системные зависимости webview нужны только для GUI. Если `cargo run` в `src-tauri`
падает на `pkg-config`, значит их нет — список пакетов в [BUILDING.md](../BUILDING.md).

## Цикл разработки: что пересобирать

Это главная таблица документа: **`cargo build` не пересобирает фронтенд**, потому что
в `tauri.conf.json` намеренно не заданы `beforeBuildCommand`/`beforeDevCommand`.

| Что изменили | Что сделать |
|---|---|
| `src/*.rs` (ядро) | `cargo test`, затем `cd src-tauri && cargo run` |
| `src/dates.rs` (даты, периоды) | `cargo test` — там же тесты разбора и группировки |
| `categories.toml` | `cd src-tauri && cargo run` (файл вшивается через `include_str!`) |
| `src-tauri/src/main.rs` | `cd src-tauri && cargo run` |
| `ui/src/*` | `cd ui && npm run build`, затем `cd ../src-tauri && cargo run` |
| `ui/src/*` + хотите горячую перезагрузку | два терминала: `cd ui && npm run dev` и `cd src-tauri && cargo tauri dev` |
| `src-tauri/tauri.conf.json`, `capabilities/` | `cd src-tauri && cargo run` (читается при компиляции) |
| `src-tauri/icons/*` | пересборка и `cargo tauri build` для бандлов |

Забыть пересобрать фронтенд — самая частая причина «изменения не применились»:
Tauri в релизном режиме отдаёт вшитый `ui/dist`, а не исходники.

## Рецепт: изменить списки ключевых слов

**Через интерфейс** — вкладка «Категории»: правьте слова, вес и приоритет, затем
«Сохранить». Настройки попадут в рабочий конфиг (рядом с exe или в пользовательскую
папку). Кнопка «Сделать стандартными» запомнит набор как эталон для сброса.

**Через файл** — правьте `categories.toml` в корне. Это стандарт, который вшивается
в бинарь при компиляции, поэтому после правки нужна пересборка.

Практика настройки:

- пишите **корень слова** без окончания: `газоанализ` покроет все формы;
- дублируйте написания с `ё` и без, если слово её содержит: `отчет`, `отчёт`;
- короткие слова (`пк`, `фн`, `пос`) дают ложные срабатывания — уточняйте контекст
  (`фискальн` вместо `фн`);
- если новая категория «не срабатывает», почти всегда её перебивает старая с тем же
  словом: либо добавьте слово старой категории в `exclude`, либо поднимите `weight`,
  либо сузьте её `include`;
- проверить результат удобно на вкладке «Данные» с фильтром по категории.

## Рецепт: новая команда IPC

1. **Бэкенд** — добавьте функцию в `src-tauri/src/main.rs`:

   ```rust
   #[tauri::command]
   fn my_command(file_index: usize, state: State<'_, AppState>) -> Result<MyResponse, String> {
       // ...
   }
   ```

   Тяжёлую работу (чтение файлов, классификацию) оборачивайте в
   `tauri::async_runtime::spawn_blocking`.

2. **Регистрация** — допишите имя в `tauri::generate_handler![...]`. Без этого
   `invoke` вернёт ошибку «command not found».

3. **Фронтенд** — добавьте обёртку в `ui/src/api.ts` рядом с остальными:

   ```ts
   export const myCommand = (fileIndex: number): Promise<MyResponse> =>
     invoke("my_command", { fileIndex });
   ```

   Аргументы в JS пишутся camelCase, в Rust — snake_case; Tauri преобразует сам.
   Параметры `State` и `WebviewWindow` из JS не передаются.

4. **Разрешения** — если команда обращается к плагину (диалоги, fs, shell), добавьте
   соответствующий `permission` в `src-tauri/capabilities/default.json`. Доступ к
   вашему собственному коду через `invoke` разрешений не требует.

5. **Пересборка** — `cd src-tauri && cargo run` и `cd ui && npm run build`, если
   менялся фронтенд.

## Рецепт: новая вкладка в интерфейсе

1. Добавьте кнопку в блок `.tabs` в `ui/src/main.ts`:

   ```html
   <button class="tab" data-tab="reports">Отчёты</button>
   ```

2. Добавьте панель с идентификатором `panel-reports` (шаблон имени обязателен:
   переключение вкладок ищет `panel-${data-tab}`).

3. Создайте `ui/src/reports.ts` с функцией `initReports()` и вызовите её в конце
   `main.ts` рядом с другими `init*`.

4. Если вкладке нужны свежие данные при входе, добавьте ветку в обработчик
   переключения вкладок — как сделано для `data` с вызовом `refreshDataViewer()`.

## Рецепт: новый столбец или фильтр на вкладке «Данные»

- **Фильтрация и пагинация** — в `get_classified_page` (бэкенд): файл может содержать
  десятки тысяч строк, поэтому выборка делается на стороне Rust, а не в браузере.
  Добавьте аргумент в команду, поле в `DataPageResponse` и параметр в
  `getClassifiedPage` (`api.ts`), затем прокинуть его из `dataViewer.ts`.
- **Отображение** — `dataViewer.ts` рендерит таблицу из `res.headers` и `res.rows`;
  скрытие столбцов реализовано на клиенте через `hiddenColumns` и не требует
  изменений в бэкенде.
- **Сводка** — агрегаты для вкладки «Графики» считает `charts.ts` из `FileSummary`,
  которые возвращает `classify_files`.

## Рецепт: изменить Excel-отчёт

- Лист «Данные» — `save_report_filtered` в `src/lib.rs`.
- Лист «Статистика» — `add_statistics_sheet` в `src/report.rs`: таблица, итоговая
  строка, блок периодов, вставка диаграмм через `sheet.insert_chart(row, col, &chart)`.
- Разбивка по периодам считается функцией `period_counts` в `src/lib.rs` — её же
  использует команда `get_dataset` для графика динамики, поэтому отчёт и интерфейс
  не разойдутся.

Помните: `worksheet.autofit()` вычисляет ширины **в момент вызова**, поэтому
вызывайте его после записи тех строк, по которым хотите считать ширину. Диаграммы
ссылаются на диапазоны листа «Статистика», поэтому при изменении порядка строк
правьте и диапазоны в `set_categories`/`set_values`.

## Рецепт: изменить отбор по датам

- Колонки-кандидаты и разбор значений — `src/dates.rs`
  (`DATE_COLUMN_CANDIDATES`, `parse_cell`, `parse_text`).
- Границы периода и группировка — `DateFilter` и `GroupBy` там же.
- Интерфейс: панель периода в `ui/src/main.ts`, состояние и пресеты в
  `ui/src/filters.ts`. Модуль публикует события через `onPeriodChange`, на них
  подписаны таблица данных (`dataViewer.ts`) и графики (`charts.ts`).

Проверка после правок: `cargo test` покрывает разбор серий Excel, текстовые форматы,
границы ISO-недель и отбор строк.

## Рецепт: изменить алгоритм классификации

Алгоритм живёт в `CategoriesConfig::classify` (`src/categories.rs`). После правки:

1. обновите тесты в `tests/defaults.rs`, если меняется смысл полей;
2. проверьте на реальной выгрузке: `cargo run -- tickets.xlsx out.xlsx` — в консоль
   печатается распределение по категориям, удобно сравнивать «до/после»;
3. обратите внимание на производительность: `classify` вызывается для каждой строки
   и перебирает все категории со всеми словами. Для 30 тысяч строк это терпимо, но
   добавление регулярных выражений потребует предкомпиляции.

## Тесты

```bash
cargo test          # юнит-тесты ядра + tests/defaults.rs
cargo test --locked # то же, что запускает CI
```

Что покрыто: стандартный набор правил (валидность, наличие настроенных слов,
приоритеты, совпадение с рабочим конфигом) и определение доступности записи в папку.
Логика GUI и фронтенда тестами не покрыта — при правках проверяйте вручную.

## Версионирование и релиз

Версия хранится в трёх местах и должна совпадать:

- `src-tauri/tauri.conf.json` → `version` (её использует `tauri build` для имён файлов)
- `src-tauri/Cargo.toml` → `version`
- `Cargo.toml` → `version` (ядро и CLI)

Чек-лист выпуска:

```bash
# 1. поднять версию в трёх файлах, например до 0.3.0
# 2. прогнать тесты и собрать локально
cargo test && (cd ui && npm run build) && (cd src-tauri && cargo tauri build)
# 3. закоммитить и отправить
git add -A && git commit -m "Версия 0.3.0" && git push
# 4. поставить тег ровно с той же версией
git tag v0.3.0 && git push origin v0.3.0
```

Тег запускает сборку на трёх ОС и создаёт **черновик релиза** — опубликовать его
нужно вручную в разделе Releases. Повторно использовать номер уже выпущенного тега
не стоит: ассеты с теми же именами конфликтуют при повторной загрузке, поэтому
следующий выпуск делайте новым номером.

## Грабли

- **Изменения в `ui/src` не видны** — не пересобран фронтенд. `npm run build` в `ui`,
  затем перезапуск приложения.
- **`cargo tauri build` падает с «frontendDist ... doesn't exist»** — не собран
  `ui/dist`. Хуки сборки в `tauri.conf.json` не заданы намеренно: Tauri разрешает
  `cwd` хука относительно своего процесса, и при запуске из корня репозитория и из
  `src-tauri` получаются разные каталоги.
- **Диалог выбора файлов молчит** — нет разрешения `dialog:default` в
  `capabilities/default.json` или приложение не пересобрано после его правки.
- **Перетаскивание файлов не работает** — Tauri перехватывает drag-and-drop нативно,
  HTML5-события путей не отдают. Используйте `getCurrentWebview().onDragDropEvent`,
  как в `upload.ts`.
- **Во вкладке «Категории» ошибка про список категорий** — рассинхрон имён полей:
  в JSON должно быть `categories`, в TOML — `[[category]]`. За совместимость
  отвечает `#[serde(alias = "category")]`.
- **На Windows открывается лишнее окно консоли** — так и должно быть в debug.
  Консоль убирается атрибутом `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`,
  который действует только в release.
- **CI: установщики не появляются в артефактах** — шаг выгрузки должен иметь
  `if: always()`, иначе падение шага релиза отменяет и выгрузку.
- **CI: `Resource not accessible by integration`** — `GITHUB_TOKEN` без права
  `contents: write`. Настройка репозитория Settings → Actions → General → Workflow
  permissions; изменение действует только на **новые** запуски, «Re-run» сохраняет
  старый контекст прав. Запасной вариант — секрет `RELEASE_TOKEN` с PAT.
- **Правки правил не влияют на сохранённый отчёт** — результат берётся из кэша по
  имени файла; нажмите «Классифицировать» заново после изменения правил.
- **Английское слово не находит заявки** — проверьте написание: `wifi` и `wi-fi`
  для поиска считаются разными, слитное написание нужно добавлять отдельным словом.
  Регистр и вид дефиса значения не имеют.
- **Период не отбирает заявки** — в файле нет колонки с распознаваемой датой либо
  значения не парсятся; подпись в панели периода скажет, какая колонка найдена.

## Отладка

- **Ядро и CLI** — обычные `println!` и `cargo run`; CLI печатает распределение по
  категориям, это быстрый способ оценить эффект правок правил.
- **Фронтенд** — `cd ui && npm run dev` и открыть `http://localhost:1420` в браузере:
  работает разметка и стили, но вызовы `invoke` упадут, потому что вне Tauri нет
  бэкенда. Полноценно — `cargo tauri dev` (там доступны DevTools).
- **В релизной сборке DevTools недоступны**, лог-файла нет: диагностируйте по
  сообщениям в статус-строках интерфейса, которые модули пишут в `.status-line`.
