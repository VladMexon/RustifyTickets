# RustifyTickets

Классификация заявок service desk по ключевым словам: приложение читает Excel-выгрузку,
распределяет заявки по категориям, показывает графики и сохраняет отчёт с диаграммами.

Проект состоит из консольной утилиты и настольного приложения (Tauri + TypeScript).
Ядро классификации общее для обоих интерфейсов.

## Возможности

**Классификация**

- Правила хранятся в `categories.toml` и правятся без перекомпиляции
- Взвешенное сопоставление: побеждает категория с наибольшей суммой весов совпавших слов
- Слова-исключения запрещают категорию для конкретной заявки
- Сопоставление по подстроке без учёта регистра: `Wi-Fi`, `VPN`, `ORA` в правилах
  находят и `wi-fi`, и `wi–fi`, и `wi fi`

**GUI (Tauri)**

- Загрузка одного или нескольких `.xlsx`: диалог выбора и перетаскивание в окно
- Отбор заявок по периоду из колонки «Время создания»: произвольный диапазон,
  пресеты (последний и предыдущий месяц, 7 и 30 дней) и группировка по месяцам
  или неделям — фильтр действует на таблицу, графики и отчёт
- Вкладка «Данные» — просмотр результата с пагинацией, поиском, фильтром по категории
  и скрытием ненужных столбцов
- Вкладка «Графики» — кольцевая диаграмма долей, топ-10 категорий, динамика по
  месяцам или неделям и сводная таблица за выбранный период
- Вкладка «Категории» — редактор ключевых слов с весами, приоритетами, поиском
  и откатом к стандартным правилам
- Сохранение отчёта в Excel: лист с данными за период, лист «Статистика»
  с разбивкой по месяцам и неделям и тремя встроенными диаграммами, читаемые даты
- Портативная версия для Windows (один exe, без установки)

**CLI**

- Пакетная обработка без GUI: `cargo run -- tickets.xlsx classified_tickets.xlsx`

## Быстрый старт

Нужен Rust 1.85+ и Node.js 20+. Для GUI — системные зависимости webview
(подробности в [BUILDING.md](BUILDING.md)).

```bash
# CLI
cargo run -- tickets.xlsx classified_tickets.xlsx

# GUI в режиме разработки
cd ui && npm ci
cd ../src-tauri && cargo run
```

Перед первым запуском GUI соберите фронтенд (`cd ui && npm run build`), иначе Tauri
не найдёт `ui/dist`. При изменении `ui/src` его нужно пересобирать — подробности
в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Как это работает

```
        categories.toml ──┐
                          ▼
   .xlsx ──► src/lib.rs (ядро) ──► ClassificationResult ──► отчёт .xlsx
                    ▲                     │
                    │                     ▼
              CLI (src/main.rs)     src-tauri (команды)
                                          │  IPC (invoke/events)
                                          ▼
                                    ui/ (TypeScript)
```

Ядро ничего не знает про интерфейс: оно принимает путь к файлу и набор правил,
возвращает строки с категориями и статистику. CLI вызывает ядро напрямую,
GUI — через Tauri-команды. Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Конфигурация категорий

Стандартный набор правил лежит в `categories.toml` и вшивается в бинарь при сборке.
Рабочий конфиг ищется в порядке:

1. рядом с исполняемым файлом (портативная версия);
2. в текущей папке (запуск из репозитория);
3. рядом с exe, если папка доступна для записи;
4. в пользовательской папке настроек — `%APPDATA%\RustifyTickets` (Windows)
   или `~/.config/rustifytickets` (Linux/macOS).

В GUI правила удобнее править на вкладке «Категории»: кнопка «Сделать стандартными»
запоминает текущий набор как эталон, к которому возвращает «Сбросить к стандартным».

Формат файла:

```toml
version = 2

[[category]]
name = "Газоанализатор"
priority = 2
weight = 1
include = ["газоанализ", "датчик газ"]
exclude = ["отчет"]
```

## Сборка и релизы

```bash
cargo test                                  # тесты ядра
cd ui && npm run build && cd ..             # фронтенд
cd src-tauri && cargo tauri build           # установщики под текущую ОС
```

CI (`.github/workflows/build.yml`) на каждый коммит и pull request прогоняет только
тесты ядра. Полная сборка на Linux, Windows и macOS запускается по тегу вида `v0.3.0`
(тогда же создаётся черновик релиза) или вручную — Actions → Build → Run workflow
с флагом `build`. Подробности — в [BUILDING.md](BUILDING.md).
